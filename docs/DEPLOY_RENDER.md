# Deploying CrossPay on Render

CrossPay ships a Render Blueprint (`render.yaml`). The current demo runs at <https://crosspay-i4gl.onrender.com>.

## What the Blueprint creates

| Setting | Value | Why |
|---|---|---|
| Service | one Python web service, `crosspay` | |
| Start command | `gunicorn --workers 1 --threads 16 --timeout 120 --bind 0.0.0.0:$PORT "crosspay:create_app('prod')"` | the live feed bus, the AI job queues and the rate limiter are in-process, so there must be exactly one worker; threads give concurrency (each open live-feed tab holds one) |
| Health check | `/healthz` | a database round trip, no auth |
| Disk | 1 GB at `/var/data` | SQLite database, ledger JSON and uploads survive deploys (`DB_PATH`, `LEDGER_PATH`, `UPLOAD_DIR`) |
| Plan | `starter` | persistent disks need a paid plan |
| Auto-deploy | on | every push to the connected branch redeploys |

## First deploy

1. In the Render dashboard choose **New → Blueprint**, connect the GitHub repository and pick the `main` branch.
2. Render reads `render.yaml` and asks for the values marked `sync: false`:
   - `DEMO_SME_PASSWORD` and `DEMO_ADMIN_PASSWORD` (the demo accounts' passwords)
   - `GROQ_API_KEY`, `NVIDIA_API_KEY`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` (optional: leave any empty and that provider is skipped)
   - `EXCHANGE_RATE_API_KEY` (optional; open.er-api.com works without a key)
3. `SECRET_KEY` and `LEDGER_SIGNING_KEY` are generated by Render (`generateValue: true`). Do not change
   `LEDGER_SIGNING_KEY` later: existing audit records would no longer verify.
4. Apply. When the deploy is live, `GET /healthz` returns `{"status": "ok"}`.

## Updating

Merging into `main` redeploys automatically. If a deploy did not start, open the service and choose
**Manual Deploy → Deploy latest commit**. Static files are served with `Cache-Control: no-cache`, so a normal reload
picks up new CSS and JS.

## Operating notes

- `DEMO_MODE=1` (the default in `render.yaml`) enables one-click logins, demo scenarios and the dry-run simulator.
  Set it to `0` for a closed deployment.
- `LLM_ENABLED=1` turns the advisory AI on; `/admin/ai` has a runtime kill switch, the daily budget and a self-test.
- `VELOCITY_BURST_1H` (default 5) sends an SME's fifth payment within an hour to HOLD. Set it to `0` to switch the rule
  off.
- `AI_BACKFILL=1` queues AI explanations for the ten most recent payments without one at startup, spaced 12 s apart so
  free-tier provider limits are not exceeded.
- Never commit `.env` or any key. Every secret lives in the Render dashboard.
