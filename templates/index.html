Cross-border payments that explain their risk before they settle.

An SME submits a payment. CrossPay converts it at a live rate, scores it with a Random Forest built from the SME's own history, and a deterministic policy approves it onto a signed ledger, holds it for a compliance officer, or blocks it. An optional AI layer explains the decision, but never makes it.

{{ tile('layers', 'blue', 'sm') }}How a payment is decided

The same input always gives the same decision. AI signals can only send a payment to a human.

{{ tile('check', 'teal') }}

Low risk: approve

Score below the review threshold. The settlement record is hashed, mined into a PoW block and signed into the HMAC audit chain in one database transaction.

model → policy → block + audit record → commit
{{ tile('pause', 'amber') }}

Medium risk: hold

A compliance officer reviews the evidence (with an optional AI copilot), writes a reason in their own words, and releases or rejects.

policy → HOLD → officer decision → audit record
{{ tile('ban', 'red') }}

High risk: block

Score above the block threshold, or the model's class is HIGH. Nothing is mined; the decision is still signed into the audit chain.

policy → BLOCKED → audit record only
